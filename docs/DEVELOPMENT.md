# 実装メモ

## 20秒のゲームに絞る

FERRY 20は、左右に動く船をタップで止めるタイミングゲームです。入力はひとつに絞り、短いプレイと再挑戦を繰り返せる構成です。

表示は480×640を基準として、縦横比を保ったまま画面中央へ拡縮します。船、港、波、文字はAndroid Canvasで描画します。

中央との距離が30以内なら100点、75以内なら50点。2回目以降の連続成功で10点ずつ追加し、追加分は100点を上限にします。範囲外のタップは連続成功をリセットします。判定後は650ミリ秒、停止位置と結果を表示します。

## Rokid側面タップへの対応

保存された実機調査では、`ROKID,`で始まる名前の入力デバイスから、`KEYCODE_NOTIFICATION`とスキャンコード204を持つ接触イベントが届き、その後にENTERが届きました。

ゲームはこの条件を満たす接触イベントを先に判定します。同じデバイスから900ミリ秒以内に届いたENTERは、ひとつの操作から発生した後続信号として除外します。キャンセルされたキーイベントとリピートも考慮しています。

これは確認した端末の入力に合わせた実装です。Rokid製品すべてに共通する仕様としては扱いません。通常のENTER、DPAD_CENTER、SPACE、ゲームパッドAと画面のタッチアップにも対応します。

## 音とゲーム描画

音は22,050Hz・モノラルPCMをアプリ内で合成します。開始、成功、中央成功、失敗、終了の5効果音と、音程を変えて鳴らすBGMがあります。

実機調査で音声操作が描画を待たせる例があったため、効果音・BGMの再生操作を専用のワーカースレッドに分けています。中断後に古い音が再生されないよう、世代番号で待機中の処理を無効化しています。

## 中断・保存

Activityが背面に回ると描画と音声を停止し、復帰時に中断時間をタイマーや演出時間から差し引きます。最高得点はSharedPreferencesに保存します。プロセスが終了した場合のプレイ途中の復元は実装していません。

## 公開準備で整えたこと

ゲームとテストのJava実装を維持し、公開向けの環境設定を整えました。ソースの整形は改行・行末・ファイル末尾の空白の整理にとどめています。

- SDK・JDKの場所を環境変数などで指定する手順。
- テストする端末IDの明示指定。
- アプリとInstrumentationテストの署名鍵の共有。
- 生成物、端末ログ、署名鍵をGitに含めない設定。
- 実際のビルド指定に合わせたtarget SDK表記。
